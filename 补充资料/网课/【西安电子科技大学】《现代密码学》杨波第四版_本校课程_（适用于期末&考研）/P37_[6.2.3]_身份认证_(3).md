## 一、公钥证书（Public Key Certificate）

### 1.1 为什么需要证书？

在公钥密码学中，任何人都可以声称"我是 Alice"，并发布一个公钥。但**如何证明这个公钥确实是 Alice 的？**

> **证书的作用**：将用户的**身份**与**公钥**安全地绑定。

### 1.2 证书的内容

一个 X.509 数字证书通常包含：

| 字段 | 说明 |
|:----:|:------|
| **主体**（Subject） | 证书持有者的身份信息 |
| **公钥** | 持有者的公钥 |
| **颁发者**（Issuer） | 签发证书的 CA |
| **有效期** | 证书生效和失效时间 |
| **签名** | CA 对上述信息的**数字签名** |

### 1.3 信任链

```
根 CA（自签名证书）
  └─ 签发 → 中级 CA 证书
               └─ 签发 → 用户证书
```

**信任锚**（Trust Anchor）：根 CA 的证书被**预置**在操作系统/浏览器中。

---

## 二、认证过程

1. Alice 将她的证书发送给 Bob
2. Bob 验证 CA 的签名（证明证书未被篡改）
3. Bob 信任 CA → 信任 CA 绑定的关系 → 相信公钥确实属于 Alice

**关键**：CA（证书权威机构）是可信的第三方，其签名保障了证书的真实性。
