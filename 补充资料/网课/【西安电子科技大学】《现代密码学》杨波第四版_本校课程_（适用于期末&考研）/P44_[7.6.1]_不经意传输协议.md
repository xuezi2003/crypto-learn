## 一、为什么需要不经意传输？

### 1.1 生活中的例子

Alice 想从在线音乐网站下载一首歌（歌手 A 或 B 的歌），她只付了一首歌的钱：

- Alice 不想让网站知道她下载了**哪首歌**（隐私保护）
- 网站要确保 Alice **只下载了一首**（防止盗版）

> 这就像现实中的房屋中介——你只要买一次房子，所有中介都给你打电话推房子。**你的偏好被泄露了**。

### 1.2 核心需求

> **不经意传输**（Oblivious Transfer, OT）：发送者发送多条消息，接收者选择其中一条，但**发送者不知道接收者选择了哪一条**。

---

## 二、1-out-of-2 不经意传输

### 2.1 定义

最常见的 OT 协议是 **1-out-of-2 OT**：

- 发送者 $S$ 有两条消息：$m_0, m_1$
- 接收者 $R$ 选择 $b \in \{0, 1\}$
- $R$ 得到 $m_b$，但 $S$ **不知道** $b$ 的值
- $R$ 不能知道另一条消息 $m_{1-b}$

### 2.2 基于 RSA 的 OT 协议

```
Sender（有 m₀, m₁）           Receiver（选择 b）
       │                            │
       ├─ 生成 RSA 密钥对 (e, d, n) │
       │  发送 (e, n) ──────────→   │
       │                            ├─ 选择随机数 k
       │                            ├─ x = k^e mod n
       │                            │  (只有 Receiver 知道 k)
       │                            │
       │  ←──── x_b = x + b ─────── │
       │                            │
       ├─ k₀ = (x_b - 0)^d mod n   │
       ├─ k₁ = (x_b - 1)^d mod n   │
       │                            │
       ├─ C₀ = m₀ ⊕ k₀            │
       ├─ C₁ = m₁ ⊕ k₁            │
       │  ────────→ C₀, C₁        │
       │                            │
       │                 m_b = C_b ⊕ k  ✅
```

## 三、OT 的应用

| 应用 | 说明 |
|:----:|:------|
| **安全多方计算** | OT 是 MPC 的基础原件之一 |
| **隐私检索** | 从数据库获取记录而不暴露查询内容 |
| **电子交易** | 买家选择商品而不暴露偏好 |
