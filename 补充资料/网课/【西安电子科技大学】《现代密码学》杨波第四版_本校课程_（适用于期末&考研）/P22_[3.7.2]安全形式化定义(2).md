## 一、IND-CPA 安全（选择明文攻击下的不可区分性）

### 1.1 攻击者能力

- 可以获得**公钥** $PK$
- 可以**任意选择明文**并获取对应的密文（加密 oracle）
- **不能**调用解密 oracle

### 1.2 安全游戏

```
挑战者                          敌手 A
  │                                │
  │—— 生成 (PK, SK) ──────────→ PK│
  │                                │
  │  （敌手可进行多项式次加密查询）  │
  │                                │
  │ ←─ 提交 m₀, m₁（|m₀|=|m₁|）── │
  │                                │
  ├─ b ← {0,1}                    │
  ├─ C* = Enc(PK, m_b) ──────→    │
  │                                │
  │  （继续允许加密查询）           │
  │                                │
  │ ←──── 输出猜测 b' ────────     │
  │                                │
  └─ 若 b' = b，敌手获胜          │
```

**安全要求**：对于任何多项式时间敌手：
$$\Pr[b^{\prime} = b] \leq \frac{1}{2} + \text{negl}(n)$$

### 1.3 哪些方案满足 IND-CPA？

| 方案 | IND-CPA? |
|:----:|:---------:|
| 教科书 RSA（确定性） | ❌ 不满足（相同的明文→相同的密文） |
| RSA-OAEP | ✅ 满足 |
| ElGamal | ✅ 满足（概率性加密） |
| Paillier | ✅ 满足 |

## 二、IND-CCA1 安全

### 2.1 攻击者能力

- 选择明文加密能力（任意次数）
- 在**获得目标密文之前**，可以查询解密 oracle

### 2.2 与 CPA 的区别

敌手在挑战前可行解密查询，但挑战后**不能**再进行解密查询。

这是一个**中间级别**的安全。

---

## 三、IND-CCA2 安全（适应性选择密文攻击）

### 3.1 攻击者能力

- **任何时候**（挑战前后）都可以查询解密 oracle
- **唯一限制**：不能直接查询目标密文 $C^*$ 的解密

### 3.2 标准安全要求

> 现代公钥加密的**安全标准**是 **IND-CCA2**！

这是因为：
- 实际系统中，攻击者可能诱导合法用户解密一些看似随机的密文
- 如 RSA 的盲化攻击（P17 所述）就是利用了非 CCA2 安全的弱点

### 3.3 哪些方案满足 IND-CCA2？

| 方案 | IND-CCA2? |
|:----:|:----------:|
| 教科书 RSA | ❌ |
| RSA-OAEP | ✅ |
| 教科书 ElGamal | ❌（乘法同态可被利用） |
| CCA 安全的 ElGamal 变种 | ✅ |
| Cramer-Shoup | ✅ |

---

## 四、总结对比

| 安全级别 | 加密查询 | 挑战前解密查询 | 挑战后解密查询 | 实际意义 |
|:--------:|:--------:|:--------------:|:--------------:|:--------:|
| **IND-CPA** | ✅ 任意 | ❌ | ❌ | **最低要求**，抗窃听 |
| **IND-CCA1** | ✅ 任意 | ✅ 任意 | ❌ | 中间级别 |
| **IND-CCA2** | ✅ 任意 | ✅ 任意 | ✅ 任意（除 C*） | **当前标准** |

---

## 五、关于明文长度的要求

在所有安全游戏中，要求敌手提交的 $m_0$ 和 $m_1$ **长度相同**——否则，通过观察密文长度就能区分，这就失去了"不可区分"的意义。
