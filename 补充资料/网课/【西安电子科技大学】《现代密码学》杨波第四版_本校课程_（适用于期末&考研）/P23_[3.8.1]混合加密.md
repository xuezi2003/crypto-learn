## 一、为什么需要混合加密？

### 1.1 两种加密方式的优缺点

| 特性 | 对称加密（私钥） | 非对称加密（公钥） |
|:----:|:----------------:|:------------------:|
| **密钥管理** | ❌ 需要提前共享密钥 | ✅ 公钥公开，私钥自保 |
| **加密速度** | ✅ **非常快**（异或、移位、查表） | ❌ **非常慢**（模指数运算） |

对称加密：
- **缺点**：密钥协商困难（需要提前共享密钥）
- **优点**：加密速度快

非对称加密：
- **缺点**：加密速度慢（模指数运算非常耗时）
- **优点**：密钥管理方便

### 1.2 核心思路

> **混合加密** = **公钥加密协商会话密钥 + 对称加密加密数据**

```
发送者                                   接收者
  │                                        │
  │ ① 生成随机会话密钥 K                   │
  │                                        │
  │ ② 用接收者公钥加密 K：                 │
  │    C_K = Enc_PK(K)                     │
  │                                        │
  │ ③ 用对称加密加密消息：                 │
  │    C_M = Enc_K(M)                      │
  │                                        │
  │ ④ 发送 (C_K, C_M) ──────────────→     │
  │                                        │
  │                   ⑤ 用私钥解密得 K     │
  │                   ⑥ 用 K 解密得 M     │
```

## 二、实际应用

### 2.1 HTTPS/TLS

HTTPS 的握手过程就是混合加密的典型应用：

| 步骤 | 加密方式 | 作用 |
|:----:|:--------:|:-----|
| ① 证书验证 | 公钥加密（RSA/ECC） | 验证服务器身份 |
| ② 密钥协商 | 公钥加密（DH/ECDHE） | 协商对称会话密钥 |
| ③ 数据传输 | **对称加密**（AES） | 加密实际内容 |

### 2.2 PGP 加密

PGP（Pretty Good Privacy）也采用混合加密：
- 用 RSA/ElGamal 加密会话密钥
- 用 IDEA/AES 加密文件内容

### 2.3 混合加密的效率优势

假设消息长度为 $n$ 比特：
- 纯公钥加密：$n$ 次模指数运算（极慢）
- 混合加密：**1 次**模指数运算（加密会话密钥）+ $n$ 次对称加密运算（极快）

## 三、混合加密的安全性

理论上可以证明：
> 如果公钥加密方案是 IND-CCA2 安全的，**并且**对称加密方案是安全的，则混合加密方案也是安全的。

---

## 四、关键点

| 要点 | 说明 |
|:----:|:------|
| **会话密钥** | 每次通信**随机生成**，用完即弃 |
| **数据加密** | 使用对称密码（AES、SM4 等） |
| **密钥封装** | 使用公钥密码（RSA、ECC 等） |
| **安全性** | 结合了两者的优点 |
