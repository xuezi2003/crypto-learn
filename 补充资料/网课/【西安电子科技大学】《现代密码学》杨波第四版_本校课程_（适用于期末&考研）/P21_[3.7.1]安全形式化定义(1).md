## 一、为什么要安全形式化定义？

> **怎么衡量一个加密方案是否安全？** 这是密码学最核心的问题之一。

如果没有严格的形式化定义，仅凭"感觉安全"就去使用——那很可能不安全。

### 1.1 "教科书式"安全是不够的

教科书上只讲原理的加密方案，**没有实际应用价值**，甚至可以说是不安全的。

---

## 二、All-or-Nothing Secrecy（要么全得到，要么全得不到）

### 2.1 定义

对于给定的密文 $C$，攻击者的任务是**得到完整的明文 $m$**。

- 攻击者要么**全部恢复**明文，要么**什么也得不到**
- 少一个比特都不行

### 2.2 问题

这个定义太弱了——因为：

- 攻击者可能只恢复出 **明文的 90%**
- 或者恢复出**密钥的某些比特**
- 这些都不满足"全部得到"，但已经造成了巨大危害！

---

## 三、抵抗被动攻击（Passive Attack Resistance）

### 3.1 要求

加密方案只能抵抗被动攻击：
- 攻击者只能**窃听**
- 不能主动修改密文
- 不能要求解密 oracle

### 3.2 局限

这个要求也太弱了——真实世界中的攻击者往往可以做更复杂的事。

---

## 四、安全级别的分层

从弱到强，公钥加密的安全性分为多个级别：

| 安全级别 | 全称 | 攻击者能力 | 说明 |
|:--------:|:----:|:----------:|:----:|
| **IND-CPA** | 选择明文攻击下的不可区分性 | 可任意选择明文加密 | **最低要求** |
| **IND-CCA1** | 非适应性选择密文攻击 | 解密前可查询解密 oracle | 中间级别 |
| **IND-CCA2** | **适应性选择密文攻击** | 任何时候可查询解密 oracle | **当前标准要求** |

> **教科书 RSA 和 ElGamal 只达到 IND-CPA 安全**，需要经过 OAEP 等填充改进才能达到 IND-CCA2 安全。

---

## 五、安全游戏（Security Game）框架

现代密码学中，安全性通过**敌手与挑战者之间的游戏**来定义：

```
挑战者                               敌手（攻击者）
   │                                      │
   ├── 生成密钥对 (PK, SK) ──────────→ PK│
   │                                      │
   │                                      │
   │     （敌手可以进行查询操作）          │
   │                                      │
   │    (在 CPA/CCA 游戏中,               │
   │     敌手可以要求加密/解密)           │
   │                                      │
   │  ←──── 提交 m₀, m₁（等长） ──────    │
   │                                      │
   ├── b ∈ {0,1} 随机选择                │
   ├── C* = Enc(PK, m_b) ───────────→    │
   │                                      │
   │     （继续允许查询，                  │
   │      但不能直接查询 C* 的解密）      │
   │                                      │
   │  ←──── 输出猜测 b' ────────────      │
   │                                      │
   └── 若 b' = b，敌手获胜               │
```

**安全定义**：如果任何多项式时间敌手获胜的概率**仅比 1/2 大一个可忽略的量**，则称该方案是安全的。

## 六、本节要点

| 要点 | 内容 |
|:----:|:------|
| All-or-Nothing | 太弱，不是好的安全定义 |
| 抵抗被动攻击 | 也不充分 |
| **IND-CPA** | 加密方案的**最低安全要求** |
| **IND-CCA2** | 当前公钥加密的**标准安全要求** |
| 安全游戏 | 现代密码学定义安全的标准方法 |
