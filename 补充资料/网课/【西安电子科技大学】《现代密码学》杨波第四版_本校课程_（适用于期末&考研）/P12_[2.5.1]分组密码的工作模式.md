# P12 [2.5.1] 分组密码的工作模式

> **课程**：西安电子科技大学 · 现代密码学（杨波第四版）
> **主讲人**：陈晓峰 · 网络与信息安全学院
> **章节**：第二讲 · 私钥密码学 · 2.5.1 分组密码的工作模式

---

## 一、为什么需要工作模式？

学习了 DES、AES、SM4 等分组密码算法后，**不能直接拿来用**！需要根据不同的应用场景选择不同的**工作模式**，以：

- 隐藏明文的**统计特性**和**数据格式**
- 提高整体安全性
- 降低**删除、重放、插入、伪造**成功的概率

> 就像后面学 RSA 时也不能直接拿教科书上的算法来用——需要 OAEP 等填充模式才安全。

---

## 二、五种工作模式概览

| 模式 | 英文 | 全称 |
|:----:|:----:|:----:|
| **ECB** | Electronic Codebook | 电码本模式 |
| **CBC** | Cipher Block Chaining | 密码分组链接模式 |
| **CFB** | Cipher Feedback | 密码反馈模式 |
| **OFB** | Output Feedback | 输出反馈模式 |
| **CTR** | Counter | 计数器模式 |

---

## 三、ECB（电码本模式）

### 3.1 原理

直接使用分组密码算法，每个明文分组独立加密：

```
P₁ → [E_K] → C₁
P₂ → [E_K] → C₂
P₃ → [E_K] → C₃
...
```

- 相同的明文 → 相同的密文
- 需要**填充（padding）** 使明文长度为分组的整数倍

### 3.2 优缺点

| 优点 | 缺点 |
|:----:|:----:|
| 简单、高速、可并行 | 相同的明文分组会得到相同的密文 |
| 适合查表实现 | **泄露明文的统计信息** |
| | 易受**重放攻击** |

### 3.3 适用场景

一般**不推荐**使用（除单个分组的加密外）。

---

## 四、CBC（密码分组链接模式）

### 4.1 原理

每个分组的加密输入 = **当前明文 ⊕ 上一分组密文**

```
C₁ = E_K(P₁ ⊕ IV)
C₂ = E_K(P₂ ⊕ C₁)
C₃ = E_K(P₃ ⊕ C₂)
...
```

- 需要**初始向量 IV**（第一个分组的前一个"密文"）
- 相同的明文分组在不同位置会得到不同的密文

### 4.2 解密

```
P₁ = D_K(C₁) ⊕ IV
P₂ = D_K(C₂) ⊕ C₁
P₃ = D_K(C₃) ⊕ C₂
...
```

### 4.3 优缺点

| 优点 | 缺点 |
|:----:|:----:|
| 安全性高于 ECB | 比 ECB 慢（不能并行加密） |
| 隐藏明文统计特性 | 错误传播：一个密文分组出错，影响两个明分组 |

### 4.4 适用场景

**文件加密**、数据块加密等。

---

## 五、CFB（密码反馈模式）

### 5.1 原理

将分组密码转换为**流密码**，使用**移位寄存器**：

```
I₁ = IV（64 比特移位寄存器）
O₁ = E_K(I₁)              // 加密移位寄存器
C₁ = P₁ ⊕ O₁ 的左 j 比特   // 只取 j 比特
I₂ = (I₁ << j) || C₁       // 将 C₁ 反馈到移位寄存器右侧
O₂ = E_K(I₂)
C₂ = P₂ ⊕ O₂ 的左 j 比特
...
```

- **解密也使用加密算法**（因为密文与密钥流异或）
- 加解密共享同一函数

### 5.2 特性

- 将分组密码转为流密码，可处理**任意长度**的消息
- 错误传播：一个密文单元的差错会影响后续几个单元

### 5.3 适用场景

**字符单元**的流密码加密、**自同步**场景。

---

## 六、OFB（输出反馈模式）

### 6.1 原理

与 CFB 类似，但**反馈的是加密算法的输出**，而非密文：

```
I₁ = IV
O₁ = E_K(I₁)
C₁ = P₁ ⊕ O₁ 的左 j 比特
I₂ = (I₁ << j) || O₁ 的左 j比特   // 反馈的是 O₁（而非 C₁）
O₂ = E_K(I₂)
C₂ = P₂ ⊕ O₂ 的左 j 比特
...
```

### 6.2 CFB vs OFB

| CFB | OFB |
|:---:|:---:|
| 反馈**密文**到移位寄存器 | 反馈**加密器输出**到移位寄存器 |
| 自同步（可从错误中恢复） | 需要收发同步 |
| 差错传播有限 | **几乎无差错传播** |

### 6.3 适用场景

**高速同步系统**、噪声信道。

---

## 七、CTR（计数器模式）

### 7.1 原理

使用一个**计数器**，每加密一个分组后计数器递增：

```
C₁ = P₁ ⊕ E_K(CTR)
C₂ = P₂ ⊕ E_K(CTR+1)
C₃ = P₃ ⊕ E_K(CTR+2)
...
```

- 计数器长度 = 分组长度
- 不同分组使用不同的计数器值

### 7.2 优点

| 特性 | 说明 |
|:----:|:------|
| **可并行** | 各分组的加密相互独立 |
| **预处理** | 可提前加密计数器值，提高效率 |
| **无错误传播** | 一个密文出错不影响其他分组 |
| **随机访问** | 可解密任意指定的密文分组 |

### 7.3 适用场景

**实时性**和**速度**要求高的场合。

---

## 八、五种模式对比总结

| 模式 | 加密并行 | 解密并行 | 错误传播 | 适用场景 |
|:----:|:--------:|:--------:|:--------:|:--------:|
| **ECB** | ✅ | ✅ | 无 | 不推荐（仅单分组） |
| **CBC** | ❌ | ✅ | 一个影响两个 | 文件加密 |
| **CFB** | ❌ | ❌ | 有限 | 字符流密码 |
| **OFB** | ❌ | ❌ | 几乎无 | 高速同步系统 |
| **CTR** | ✅ | ✅ | 无 | 实时系统、随机访问 |

---

## 九、重要提醒

> 学了算法之后**不能简单粗暴直接拿来用**——就像后面学 RSA：
> - 不能直接用教科书上的 RSA 加密算法（不安全）
> - 需要配合填充方案（如 OAEP）、哈希函数等改进
> - 要结合**应用场景**选择合适的工作模式

无论是**对称密码**还是**公钥密码**，**安全使用**都是关键。
