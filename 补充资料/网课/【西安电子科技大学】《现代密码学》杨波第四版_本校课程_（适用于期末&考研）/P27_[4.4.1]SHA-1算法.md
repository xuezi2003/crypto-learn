## 一、SHA 系列发展

SHA = **Secure Hash Algorithm**（安全哈希算法），由 NIST 和 NSA 联合设计。

### 发展历程

| 版本 | 年份 | 输出 | 状态 |
|:----:|:----:|:----:|:----:|
| **SHA-0** | 1993 | 160 比特 | 因安全原因很快被撤回 |
| **SHA-1** | 1995 | **160 比特** | ❌ 已理论破译 |
| **SHA-2**（SHA-256/384/512） | 2002 | 256/384/512 比特 | ✅ 当前标准 |
| **SHA-3**（Keccak） | 2015 | 可定制 | ✅ 最新标准 |

### 为什么需要 SHA？

MD5 被破译后，需要设计更安全的哈希函数作为替代。MD5 的设计者 Rivest 本人也参与了 MD5→SHA 的过渡。

## 二、SHA-1 算法

### 2.1 基本参数

| 参数 | 值 |
|:----:|:---:|
| 输入 | 任意长消息 |
| 分组长度 | **512 比特** |
| 输出 | **160 比特**（5 个 32 位字） |
| 轮数 | **80 步**（4 轮，每轮 20 步） |

### 2.2 SHA-1 vs MD5 的改进

| 改进 | 说明 |
|:----:|:------|
| **更长输出** | 160 比特（vs MD5 的 128 比特） |
| **更多步数** | 80 步（vs MD5 的 64 步） |
| **扩展变换** | 增加了输入扩展的复杂度 |
| **前轮输入增加** | 将前轮的输入扩展到下一轮 |

### 2.3 处理流程

与 MD5 类似，SHA-1 也使用 Merkle-Damgård 结构：
1. 消息填充（使长度为 512 的倍数）
2. 初始化 **5 个** 32 位寄存器（A, B, C, D, E）
3. 逐分组处理（每分组 80 步迭代）
4. 输出 160 比特哈希值

## 三、SHA-1 的安全性

### 3.1 破译历史

| 时间 | 事件 |
|:----:|:------|
| 2005 | 王小云团队提出 SHA-1 攻击，复杂度 ${2}^{69}$ |
| 2015 | 攻击复杂度降至 ${2}^{57.5}$ |
| 2017 | Google 展示**实际碰撞**（${2}^{63}$ 次 SHA-1 计算） |
| **当前** | **SHA-1 已被完全推翻，禁止用于安全场景** |

### 3.2 当前建议

| 用途 | 建议算法 |
|:----:|:--------:|
| 文档签名 | SHA-256 或 SHA-3 |
| 证书签名 | SHA-256 |
| 区块链 | SHA-256（比特币）、Keccak（以太坊） |
| 中国标准 | **SM3**（256 比特） |

## 四、SHA-2 与 SHA-3

### SHA-2 系列

| 算法 | 输出长度 | 说明 |
|:----:|:--------:|:------|
| SHA-224 | 224 比特 | |
| **SHA-256** | **256 比特** | **最常用** |
| SHA-384 | 384 比特 | |
| SHA-512 | 512 比特 | |

### SHA-3（Keccak）

- 2015 年成为 NIST 标准
- 采用**海绵结构**（Sponge Construction），与 SHA-2 完全不同
- 可定制输出长度
- 对 SHA-2 的补充而非替代

---

## 五、哈希函数的选择建议

| 安全需求 | 推荐算法 |
|:--------:|:--------:|
| 一般安全 | **SHA-256** |
| 更高安全 | SHA-512 / SHA-3 |
| 中国标准 | **SM3** |
| ❌ 不要用 | MD5, SHA-0, SHA-1 |
