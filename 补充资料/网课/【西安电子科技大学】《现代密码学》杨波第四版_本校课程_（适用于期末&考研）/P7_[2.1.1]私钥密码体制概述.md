## 一、基本概念与定义

### 1.1 名称与别称

私钥密码体制（Private-Key Cryptosystem）又称：

| 名称         | 英文                   |
| ------------ | ---------------------- |
| 单钥密码体制 | One-Key Cryptosystem   |
| 对称密码体制 | Symmetric Cryptosystem |

与之对比，**公钥密码体制**又称双钥密码体制或非对称密码体制。

### 1.2 核心特征

**加密密钥与解密密钥相同**。更严格地说：

- 加密密钥 $K_e$ 与解密密钥 $K_d$ **相同**，即 $K_e = K_d$；
- 或者由其中一个**容易推导**出另一个：$K_e \to K_d$ 或 $K_d \to K_e$。

---

## 二、历史与优势

### 2.1 历史悠久

私钥密码体制的历史可追溯至公元前几个世纪，如 **凯撒密码（Caesar Cipher）** 即属于对称密码体制。从古代一直到 1976 年公钥密码学诞生之前，人类所使用的密码体制全部是私钥密码体制。

### 2.2 主要优势

| 优势                       | 说明                                                                                                          |
| -------------------------- | ------------------------------------------------------------------------------------------------------------- |
| **加解密速度快**     | 不依赖公钥体制中非常耗时的模指数运算（当模很大时，模指数运算极为耗时）                                        |
| **密钥相对较短**     | DES 最初为 64 比特（实际有效密钥 56 比特）；AES 有 128 / 192 / 256 比特；而 RSA 至少需要 2048 比特的模数$n$ |
| **软硬件实现成本低** | 软件和硬件均能高效实现私钥密码算法                                                                            |

---

## 三、劣势与密钥管理问题

### 3.1 核心问题：密钥协商

由于加密密钥与解密密钥相同，通信双方在通信前**必须共享一个秘密**作为种子密钥。密钥传递的两种方式：

1. **面对面协商**：双方提前面对面约定密钥；
2. **可信第三方传递**：通过可信信使（可信第三方）将密钥传递给对方。

无论哪种方式，在大规模网络中如何**安全地产生、分发和管理密钥**都非常困难。

### 3.2 网络中密钥数量的增长

在一个有 $N$ 个用户的网络中，任意两方之间需要不同的密钥（若 $A$ 与 $B$ 的密钥为 $K$，$B$ 与 $C$ 的密钥为 $K^{\prime}$，则 $K \neq K^{\prime}$，否则第三方可以获知全部通信）。

$$
\text{所需密钥数} = C_N^2 = \binom{N}{2} = \frac{N(N-1)}{2}
$$

当 $N$ 较大时，密钥数量为 **$O(N^2)$** 量级，安全管理的难度极大。

### 3.3 Kerckhoff 原则

> **Kerckhoff 原则**：密钥是密码体制的核心。如果密钥丢失，算法设计再好也没有意义。

### 3.4 公钥体制的解决

公钥密码体制恰好解决了密钥协商问题——能够高效实现密钥协商，支持一对多通信。公钥体制将在后续章节详细讲解。

## 四、私钥密码体制的分类

私钥密码体制分为**两大类**：

```
私钥密码体制
├── 流密码（Stream Cipher / 序列密码）
└── 分组密码（Block Cipher / 分块密码）
```

---

## 五、流密码（Stream Cipher）

### 5.1 一次一密（One-Time Pad）

回顾 **一次一密密码**（One-Time Pad），其加密公式为：

$$
C = M \oplus K
$$

即消息流 $M$ 与密钥流 $K$ 进行**逐比特异或**运算。

**香农（Shannon）证明**：若密钥 $K$ 满足以下条件：

1. $K$ 是**真随机数**；
2. $|K| = |M|$，即密钥与消息**等长**；
3. $K$ **仅使用一次**（One-Time Use），

则一次一密在理论上是**无条件安全的**（即使攻击者具有无穷的计算能力也无法破译）。

#### 不可破译的直观证明

对于任意一个有意义的消息 $M^*$，攻击者总可以构造密钥：

$$
K^* = C \oplus M^*
$$

使得密文 $C$ 可以被"解密"为任意有意义的消息 $M^*$。因此，给定密文后，攻击者无法确定真正的明文是什么。

#### 一次一密的优缺点

| 优点                                   | 缺点                             |
| -------------------------------------- | -------------------------------- |
| 理论上无条件安全                       | 需要产生与消息等长的真随机密钥流 |
| 效率高（仅比特异或运算，计算机最擅长） | 产生足够大的真随机数非常困难     |
|                                        | 限制了其广泛应用                 |

### 5.2 流密码 = 一次一密的弱化版本

由于无法产生足够长的真随机密钥流，流密码使用伪随机数发生器（PRNG）来产生伪随机序列作为密钥流。

$$
C = M \oplus \text{PRNG}(K)
$$

#### 流密码的安全隐患

- 无论伪随机数发生器设计得多好，伪随机序列**总存在周期**；
- 一旦出现周期，就不再是真正的随机数，从而产生安全问题。

> 流密码的核心难点在于：**如何构造足够好的伪随机序列发生器**。

### 5.3 应用领域

流密码主要用于**军事**和**外交领域**，是这些领域的主要密码体制。

## 六、分组密码（Block Cipher）

### 6.1 基本原理

分组密码是一种**多字母代换**密码，其处理流程为：

1. 将明文消息编码为数字序列；
2. 将数字序列**划分为长度为 $n$ 的分组**（block），常见的分组长度有 64、128、192、256 比特等（DES 为 64 比特）；
3. 在密钥 $K$ 的控制下，对每个分组进行**等长变换**，得到密文分组。

$$
Y = E_K(X), \quad X, Y \in \{0,1\}^n, \quad K \in \{0,1\}^t
$$

其中 $n$ 为分组长度，$t$ 为密钥长度。在大多数情况下，$n = t$（如 AES-128 中 $n = t = 128$）。

> **注**：分组长度与 64 的关系源于早期计算机内存长度的设计。

### 6.2 与流密码的区别

| 特征         | 流密码               | 分组密码                           |
| ------------ | -------------------- | ---------------------------------- |
| 代换方式     | 单字母代换           | 多字母代换                         |
| 处理单元     | 逐比特/逐字节        | 固定长度的分组（block）            |
| 输出依赖关系 | 仅与当前输入比特有关 | 与当前一组长为$n$ 的明文比特有关 |

### 6.3 分组密码设计核心

设计分组密码的关键在于：**在密钥 $K$ 的控制下，从一个足够大且足够好的置换子集中找出一个置换，使得明文和密钥之间进行充分的扩散和混淆**，最终得到密文。

#### 两个基本操作（Shannon 提出）

- **扩散（Diffusion）**：使明文的每一位影响密文的尽可能多位；
- **混淆（Confusion）**：使密文与密钥之间的统计关系尽可能复杂。

### 6.4 分组密码的设计要求

分组密码算法应满足以下要求：

#### （1）分组长度 $n$ 足够大

- 最低要求 $n \geq 64$，目前至少需要 $n \geq 128$；
- 分组太小则明文空间过小（如 $n=10$ 时仅有 ${2}^{10}$ 种可能），攻击者可以穷举遍历；
- **加密时需要对明文进行填充（padding）**，至少填充至 64 或 128 比特。

#### （2）密钥量足够大

密钥空间要足够大，否则攻击者可以通过穷举攻击（暴力攻击）奏效。

#### （3）算法足够复杂

由密钥确定置换的算法必须足够复杂，以达到充分的扩散和混淆，防止被破译。

#### （4）能抵抗各种已知的攻击

> **重要观点**：安全是相对的，不安全才是绝对的。

- 没有绝对安全的密码算法。例如 AES、RSA 等本质上都是不安全的——RSA 依赖大整数分解的困难性，目前尚无多项式时间算法，但不代表该算法不存在；量子计算机的 Shor 算法可以在多项式时间内分解大整数。
- 所有密码体制的安全性都建立在某种**计算假设**之上。
- 设计要求：至少能够抵抗**现有的已知攻击**（如差分攻击、线性攻击等）。若未来出现新攻击，则需修订、更新或重新设计算法。

#### （5）加解密简单高效

- 加解密速度快，适合软件或硬件实现；
- 如 AES 胜出的一个重要原因就是能在单片机上高效处理（8 比特即可处理）。

#### （6）数据扩展尽可能小

一般不希望有数据扩展（如将 64 比特加密为 128 或 256 比特），扩展量大会影响效率。

#### （7）差错传播尽可能小

若中间引入一个错误比特，对后续轮次的影响应尽可能小。这是一个需要**均衡考虑**的问题。

### 6.5 安全性与效率的折中

> 分组密码的设计需要在**安全性**与**效率性**之间取得折中。

例如轮数的选择：轮数越多，扩散和混淆效果越好，但效率越差。当达到充分扩散和混淆后（如 30~32 轮），再增加轮数只会增加无谓的计算量。

## 七、本节知识框架

**私钥密码体制概述**

- **定义**：加密密钥 = 解密密钥，或可相互推导
- **优势**：速度快、密钥短、实现成本低
- **劣势**：密钥协商困难，N 人网络需 C（N，2）个密钥
- **分类**
  - **流密码（序列密码）**
    - 一次一密
    - 伪随机密钥流
  - **分组密码（分块密码）**
    - 多字母代换
    - 核心：扩散 + 混淆
    - 设计要求：分组大、密钥大、算法复杂、抗攻击、高效、低扩展
- **安全观**：安全是相对的，依赖计算假设
